4.  System  Workflows
  Workflow  1:  Student  Course  Enrollment  This  workflow  demonstrates  synchronous  REST  communication  combined  with  asynchronous  
event-driven
 
notification.
 
It
 
is
 
triggered
 
when
 
a
 
student
 
requests
 
enrollment
 
in
 
a

Services  Involved  •  Course  Service  (orchestrator)  •  Student  Service  (identity  verification)  •  Notification  Service  (async  alert  delivery)   
Interaction  Sequence  
Step  From  To  Action  /  Event  
1  Student  (User)  Course  Service  
POST  /courses/{id}/enroll  —  student  submits  enrollment  request  
2  Course  Service  Student  Service  
GET  /students/validate/{id}  —  synchronous  REST  call  to  verify  student  is  active  and  eligible  3  Student  Service  Course  Service  Returns  student  status  (200  OK  or  error)  
4  Course  Service  Course  DB  
Checks  capacity  and  creates  Enrollment  record  (status:  active)  
5  Course  Service  Message  Broker  
Publishes  enrollment.confirmed  event  to  topic:  course.events  
6  Notification  Service  Message  Broker  
Consumes  enrollment.confirmed  event  from  topic:  course.events  
7  Notification  Service  Student  Service  
GET  /students/{id}  —  retrieves  student  contact  info  for  delivery  
8  Notification  Service  Student  (Email/App)  
Delivers  enrollment  confirmation  notification;  saves  Notification  record   
Data  Tables  Updated  •  Course  Service  DB:  Enrollment  table  (new  record  inserted,  course  enrolled  count  incremented)  •  Notification  Service  DB:  Notification  table  (record  created  with  status:  sent)   
Event  Details  
Event  Topic  /  Channel  Payload  
enrollment.confirmed  course.events  {  studentId,  courseId,  courseName,  enrolledAt  }
